# PM Edu — запуск на VPS

Серверная версия платформы: данные всех студентов и преподавателей хранятся на сервере, вход по логину и паролю, роли проверяются на сервере.
Работает на Node.js 18+ **без внешних библиотек** (`npm install` не нужен).

## Что внутри

| Файл / папка | Назначение |
|---|---|
| `server.js` | сервер: API, сессии, хранение данных, резервные копии |
| `public/` | сайт (интерфейс) |
| `shared/` | общая логика (та же, что в браузере) |
| `.env.example` | настройки |
| `deploy/setup.sh` | автоматическая установка на чистый сервер |
| `deploy/update.sh` | установка новой версии без потери данных |
| `deploy/pmedu.service`, `deploy/nginx-pmedu.conf` | шаблоны systemd и nginx |

## 1. Что нужно купить / подготовить

1. **VPS** с Ubuntu 22.04 или 24.04: 1 vCPU, 1–2 ГБ RAM, 20 ГБ диска достаточно для пилота (сотни пользователей).
   Если на платформе будут реальные студенты, берите сервер в Узбекистане — этого требует закон о персональных данных.
2. **Домен**, например `pmedu.uz`. В панели регистратора создайте DNS-запись типа **A**: имя `@` → IP-адрес вашего VPS.
   Подождите, пока запись заработает (обычно 10–60 минут). Проверка: `ping pmedu.uz` показывает IP сервера.

## 2. Установка (≈10 минут)

На своём компьютере (Windows: PowerShell; macOS/Linux: Терминал):

```bash
# 1) скопировать архив на сервер
scp pm-edu-server.zip root@IP_СЕРВЕРА:/root/

# 2) зайти на сервер
ssh root@IP_СЕРВЕРА
```

На сервере:

```bash
apt-get update && apt-get install -y unzip
cd /root && unzip pm-edu-server.zip -d pm-edu && cd pm-edu
sudo bash deploy/setup.sh pmedu.uz ваш@email.uz "Yorqinjon Valiyev"
```

Скрипт сам:
- установит Node.js, nginx, certbot и брандмауэр;
- создаст системного пользователя `pmedu` и папку `/opt/pmedu`;
- создаст администратора и **выведет временный пароль** (сохраните его!);
- запустит сервис, который сам поднимается после перезагрузки;
- настроит nginx и получит бесплатный HTTPS-сертификат Let's Encrypt.

Если сертификат не выдался (DNS ещё не обновился), подождите и выполните `sudo certbot --nginx -d pmedu.uz` — без HTTPS вход на сайт не работает, это защита cookie.

Откройте `https://pmedu.uz`, войдите как администратор и **смените пароль** в разделе «Sozlamalar».

## 3. Первые шаги в админке

1. Преподаватели регистрируются сами, затем администратор в «Admin paneli» меняет им роль на «Ustoz».
2. Студенты регистрируются сами (группа указывается при регистрации, например `AM-21`) — по ней преподаватель выдаёт задания.
3. Забыл пароль → администратор нажимает 🔒 рядом с пользователем и выдаёт временный пароль.

## 4. Настройки (`/opt/pmedu/.env`)

| Параметр | Что делает |
|---|---|
| `REGISTRATION=closed` | закрыть самостоятельную регистрацию |
| `ALLOWED_EMAIL_DOMAINS=tdtu.uz` | регистрироваться можно только с почтой этого домена |
| `PM_DEMO=1` | демо-режим с тестовыми данными (только для показа, **не для реальной работы**) |
| `BACKUPS_KEEP=14` | сколько дней хранить резервные копии |

После изменения: `sudo systemctl restart pmedu`

## 5. Обслуживание

```bash
sudo systemctl status pmedu          # работает ли сервис
sudo journalctl -u pmedu -n 100      # журнал ошибок
sudo systemctl restart pmedu         # перезапуск
cd /opt/pmedu && sudo runuser -u pmedu -- node server.js reset-password user@mail.uz   # сброс пароля из консоли
```

**Резервные копии** создаются автоматически раз в день: `/opt/pmedu/data/backups/db-ГГГГ-ММ-ДД.json.gz`.
Рекомендуется раз в неделю скачивать их к себе:
`scp root@IP_СЕРВЕРА:/opt/pmedu/data/backups/* ./pmedu-backups/`

Восстановление из копии:
```bash
sudo systemctl stop pmedu
gunzip -c /opt/pmedu/data/backups/db-2026-10-15.json.gz > /opt/pmedu/data/db.json
chown pmedu:pmedu /opt/pmedu/data/db.json && sudo systemctl start pmedu
```

**Новая версия сайта:** загрузите новый архив, распакуйте и выполните `sudo bash deploy/update.sh` — данные сохранятся (перед обновлением делается резервная копия).

## 6. Безопасность — что уже сделано

- Пароли хешируются на сервере алгоритмом **scrypt** со случайной солью; в браузер хеши не передаются.
- Сессия — случайный 256-битный токен в cookie `HttpOnly; Secure; SameSite=Strict`; на сервере хранится только его хеш.
- 5 неверных попыток входа → блокировка аккаунта на 5 минут; ограничение числа попыток с одного IP; журнал входов.
- Каждый пользователь получает только разрешённые ему данные (студент не видит чужие ответы, пароли, e-mail).
- Роли проверяются на сервере для каждого действия; результаты тестов **пересчитываются сервером** по банку вопросов — подделать оценку из браузера нельзя.
- Время выполнения задания преподавателя контролирует сервер.
- Заголовки безопасности: CSP, X-Frame-Options, nosniff; защита от CSRF; HTTPS и брандмауэр.
- Сервис работает под отдельным пользователем без прав администратора, с ограничениями systemd.

## 7. Ограничения текущей версии

- Данные хранятся в одном файле `db.json` (с атомарной записью и ежедневными копиями). Этого достаточно для пилота — до нескольких тысяч пользователей. Для масштаба всего университета следующий шаг — перенос в PostgreSQL.
- Вход через Google/OneID и отправка писем (восстановление пароля по e-mail) пока не подключены: пароль сбрасывает администратор.
- Вопросы «Cheksiz mashq» генерируются в браузере, поэтому для них сервер не может проверить правильность. Это только тренировка; задания преподавателя и обычные тесты проверяются сервером полностью.
